# 운영자 안내서 — NABL 홈페이지

**이 문서는 코드를 다루지 않는 관리자를 위한 것입니다.**
홈페이지 내용을 고치고, 고친 내용을 사이트에 올리고, 문제가 생겼을 때
무엇을 보면 되는지만 다룹니다.

개발 규칙이 필요하면 저장소 맨 위의 `CLAUDE.md` 를 보세요. 이 문서와 다르게,
그쪽은 코드를 고치는 사람을 위한 문서입니다.

---

## 1. 가장 중요한 한 가지

**홈페이지 내용은 Notion 에서만 고칩니다.**

구성원, 논문, 특허, 수상, 연구 과제, 소식 — 화면에 보이는 이런 내용은 전부
Notion 데이터베이스에서 가져옵니다. 홈페이지 파일을 열어 글자를 고치는 일은
없습니다. Notion 을 고치면 홈페이지가 따라옵니다.

바꾼 내용이 사이트에 **바로 보이지는 않습니다.** 왜 그런지는 2번에 있습니다.

---

## 2. 어떻게 돌아가는가 (그림으로)

```
  Notion 데이터베이스 9개
          │
          │  ① 빌드할 때 한 번만 읽어 온다
          ▼
   HTML 파일 만들기  (Netlify 가 대신 해 줍니다)
          │
          │  ② 만들어진 파일을 올린다
          ▼
     방문자가 보는 홈페이지
```

중요한 점 두 가지입니다.

**가져오는 시점은 "빌드할 때" 뿐입니다.**
홈페이지는 방문자가 접속할 때 Notion 을 보지 않습니다. 미리 만들어 둔 HTML 파일을
그대로 내려 줍니다. 그래서 빠르고 안정적이지만, **Notion 을 고쳐도 다시 빌드하기
전까지는 사이트가 바뀌지 않습니다.** 다시 빌드하는 방법은 3번에 있습니다.

**연결은 한쪽 방향입니다.**
홈페이지는 Notion 을 **읽기만** 합니다. 사이트에서 뭘 해도 Notion 데이터가
바뀌는 일은 없습니다. 안심하고 보셔도 됩니다.

### 어느 Notion DB 가 어디에 나오는가

| Notion 데이터베이스 | 홈페이지에서 보이는 곳 |
| --- | --- |
| 👤 연구원 | 연구원 목록, 각 연구원 상세 페이지 |
| 👨‍🏫 지도교수 이력 | 지도교수 페이지의 학력·경력·대외활동 |
| 🧪 연구 분야 | 연구 페이지의 연구 범위·연구 분야 |
| 💼 연구 과제 | 연구 페이지의 연구 과제 목록 |
| 📄 논문 | 논문 페이지 |
| 🧾 특허 | 특허 페이지 |
| 🏆 수상 | 수상 페이지 |
| 📰 소식 | 소식 목록, 소식 상세 페이지 |
| 📂 공개 자료 | (페이지 준비 중) |

## 3. 고친 내용을 사이트에 올리기

### 방법 A — Netlify 에서 다시 빌드 누르기 (가장 많이 쓰게 됩니다)

Notion 내용만 고쳤을 때 쓰는 방법입니다.

1. [app.netlify.com](https://app.netlify.com) 에 연구실 계정으로 로그인
2. NABL 홈페이지 사이트를 선택
3. 왼쪽 메뉴에서 **Deploys**
4. 오른쪽 위 **Trigger deploy** → **Deploy site** 클릭
5. 1~3분 기다립니다. 맨 윗줄이 **Published** 로 바뀌면 끝입니다

초록색 **Published** 가 보이면 사이트에 반영된 것입니다.
빨간색 **Failed** 면 6번(문제와 해결법)을 보세요.

### 방법 B — 코드를 고쳤을 때

코드를 고치는 사람이 GitHub 에 올리면(push) Netlify 가 **알아서** 다시 빌드합니다.
따로 누를 것이 없습니다.

### 빌드가 Notion 을 읽으려면

Netlify 에 Notion 접속 정보가 들어 있어야 합니다. 이미 설정돼 있지만, 확인하려면:

Netlify → 사이트 선택 → **Site configuration** → **Environment variables**

여기에 `NOTION_TOKEN` 과 `NOTION_..._DATA_SOURCE_ID` 아홉 개가 있어야 합니다.
**이 값들은 비밀입니다.** 메신저·이메일·문서에 붙여 넣지 마세요.
필요한 키 이름 목록은 저장소의 `.env.example` 에 설명과 함께 있습니다 (값은 비어 있습니다).

## 4. Notion 에서 지켜야 할 약속

코드가 Notion 의 **열 이름**과 **선택지 값**을 보고 동작합니다.
아래만 지키면 홈페이지가 깨지지 않습니다.

### 하지 말아야 할 것

- **열(속성) 이름을 바꾸지 마세요.** `Title`, `Publish`, `Start_date` 같은 이름입니다.
  바꾸면 그 항목이 홈페이지에서 **빈칸으로 나오거나 사라집니다.**
  꼭 바꿔야 하면 코드를 고칠 수 있는 사람에게 먼저 알려 주세요.
- **열을 삭제하지 마세요.** 쓰지 않는 열이라도 그냥 두는 편이 안전합니다.
- **선택지 값의 철자를 바꾸지 마세요.** 예: `Ongoing` → `ongoing`.

### 해도 괜찮은 것

- 데이터베이스 **이름**은 바꿔도 됩니다. 코드는 이름으로 찾지 않습니다.
- 행(항목)을 추가·수정·삭제하는 것. 이게 평소 하는 일입니다.
- 선택지를 **새로 추가**하는 것. 모르는 값이 들어와도 빌드는 성공하고,
  화면에는 Notion 에 적힌 값이 그대로 나옵니다 (번역된 라벨이 아니라 원문).
- 열을 **새로 추가**하는 것. 코드가 모르는 열은 그냥 무시합니다.

### 항목을 숨기고 싶을 때

각 데이터베이스의 **`Publish` 체크를 끄면** 그 항목은 홈페이지에서 사라집니다.
(연구원 DB 는 `홈페이지 공개`)

행을 지우지 말고 체크를 끄는 쪽을 권합니다. 나중에 되살리기 쉽습니다.

### 알아 두면 좋은 규칙 몇 가지

| 무엇 | 규칙 |
| --- | --- |
| 논문 연도 | `Published_date`(게재일) 의 연도를 씁니다. 비어 있으면 `Year` 숫자를 씁니다. 둘 다 비면 "연도 미상" 묶음으로 갑니다 |
| 특허 등록/출원 | 등록번호나 등록일이 있으면 "등록", 없으면 "출원" 으로 자동 분류됩니다 |
| 만료된 특허 | `Status` 를 `Expired` 로 두면 홈페이지에 나오지 않습니다 (`Publish` 가 켜져 있어도) |
| 연구 과제 | `Status` 가 `Ongoing` 이거나 날짜가 비면 맨 위 "진행 중" 묶음, 나머지는 시작 연도별로 최신순 |
| 영어·한국어 | 한쪽만 채워도 됩니다. 비어 있는 쪽은 채워진 쪽 글이 그대로 나옵니다 |
| 제목이 비면 | 그 행은 조용히 건너뜁니다. 오류가 나지는 않지만 화면에도 안 나옵니다 |
| 사진·이미지 | 빌드할 때 내려받아 사이트에 담습니다. 올린 직후에는 다시 빌드해야 보입니다 |

### 상세 페이지가 필요한 항목은 `Slug` 를 채우세요

연구원·소식·공개 자료는 각자 상세 페이지를 가질 수 있습니다.
그 주소를 `Slug` 열로 정합니다.

- **영문 소문자, 숫자, 붙임표(-)** 만 씁니다. 예: `hong-gildong`, `2026-lab-workshop`
- 한글·공백·대문자·밑줄은 쓸 수 없습니다
- 비워 두면 상세 페이지를 만들지 않습니다 (목록에는 그대로 나옵니다)
- **다른 행과 겹치면 안 됩니다**

## 5. 사이트를 미리 보고 싶을 때

Netlify 는 GitHub 에 올라온 변경마다 **미리보기 주소**를 만들어 줍니다.
Deploys 목록에서 각 줄을 누르면 그 시점 사이트를 볼 수 있는 주소가 나옵니다.
실수로 뭔가 어긋났을 때, 바로 전 배포를 눌러 비교해 보면 원인을 찾기 쉽습니다.

**되돌리기:** Deploys 목록에서 잘 되던 배포를 누르고
**Publish deploy** 를 누르면 그 상태로 즉시 돌아갑니다.
문제가 급할 때는 원인을 찾기 전에 먼저 되돌려 두는 것이 좋습니다.

## 6. 자주 생기는 문제와 해결법

### Notion 을 고쳤는데 사이트가 그대로입니다

가장 흔한 일입니다. **아직 다시 빌드하지 않았기 때문입니다.**
3번 방법 A 로 **Trigger deploy** 를 누르세요.

눌렀는데도 그대로라면 순서대로 확인합니다.

1. 그 행의 `Publish` 체크가 켜져 있나요?
2. 제목(`Title` 또는 `이름`)이 비어 있지 않나요? 비면 건너뜁니다
3. 브라우저가 옛 화면을 기억하고 있을 수 있습니다 — 새로고침을 강제로 하세요
   (윈도우: `Ctrl`+`Shift`+`R`, 맥: `Cmd`+`Shift`+`R`)
4. Netlify Deploys 맨 윗줄이 **Published** 인가요? **Failed** 면 아래를 보세요

### 배포가 Failed 로 끝났습니다

Deploys 에서 그 줄을 누르면 **기록(로그)** 이 나옵니다.
맨 아래쪽에 원인이 적혀 있습니다. 아래는 자주 나오는 문장들입니다.

| 로그에 보이는 말 | 뜻 | 할 일 |
| --- | --- | --- |
| `[i18n] 키 검사 실패` | 화면 문구가 한쪽 언어에만 있습니다 | 코드 문제입니다. 고칠 사람에게 로그를 전달하세요 |
| `NOTION_TOKEN` / `DATA_SOURCE_ID` 관련 | Netlify 의 Notion 접속 정보가 없거나 틀렸습니다 | 3번의 Environment variables 를 확인 |
| `401` 또는 `unauthorized` | 토큰이 만료·폐기됐거나, 그 DB 에 연결 권한이 없습니다 | 아래 "권한" 항목 참고 |
| `404` 또는 `object_not_found` | 그 DB 가 삭제됐거나 ID 가 틀렸습니다 | Notion 에서 DB 가 그대로 있는지 확인 |
| `429` | Notion 이 "너무 자주 부른다" 고 합니다 | 몇 분 뒤 다시 Trigger deploy |
| 그 밖의 알 수 없는 오류 | — | **먼저 5번으로 이전 배포를 되돌려** 사이트를 살리고, 로그를 전달하세요 |

**권한:** Notion 통합(integration)은 각 데이터베이스에서 따로 연결해 줘야 읽을 수 있습니다.
해당 DB 를 열고 오른쪽 위 `•••` → **연결(Connections)** 에서 홈페이지 통합이
들어 있는지 확인하세요. 새 DB 를 만들었을 때 자주 빠뜨리는 부분입니다.

### 어떤 항목만 빈칸으로 나옵니다

그 항목의 열 이름이 바뀌었을 가능성이 가장 큽니다 (4번 참고).
Notion 에서 그 DB 의 열 이름을 원래대로 돌리거나, 코드를 고칠 사람에게 알려 주세요.

### 연구원 사진이 안 보입니다

1. Notion `프로필 사진` 열에 파일이 올라가 있나요?
2. 올린 뒤 **다시 빌드**했나요? 사진은 빌드할 때 내려받습니다
3. 그래도 안 되면 배포 로그에서 `[assets]` 로 시작하는 줄을 보세요.
   `실패 N건` 이 있으면 그 파일만 못 가져온 것입니다 (사이트 전체는 정상)

### 목록 순서가 이상합니다

- 연구원: `홈페이지 순서` 숫자가 작은 쪽이 위로 옵니다. 비어 있으면 직책 순서를 따릅니다
- 논문·특허·수상·소식: 날짜가 최신인 쪽이 위입니다
- 숫자나 날짜가 비어 있으면 뒤로 밀립니다

### 선택지 값이 영어로 나옵니다

Notion 에 새 선택지를 추가하면, 번역이 없어 **Notion 에 적힌 값 그대로** 나옵니다.
잘못된 동작이 아닙니다. 한국어로 보이게 하려면 코드를 고칠 사람에게
"이 선택지의 한국어 라벨을 추가해 달라" 고 요청하세요.

### 주소(도메인)를 바꾸고 싶습니다

학교 도메인이 정해지면 코드 한 곳(`src/config/site.ts`)만 고치면 됩니다.
코드를 고칠 사람에게 새 주소를 알려 주세요.

## 7. 사람이 바뀔 때 (인수인계)

이 사이트는 개인 계정에서 시작해 **연구실 공용 계정으로 넘기는 것을 전제**로
만들어졌습니다. 개인에게만 딸린 값은 코드에 들어 있지 않습니다.

넘길 때 확인할 것:

- [ ] GitHub 저장소 소유권이 연구실 조직(`nabl-lab`)에 있는지
- [ ] Netlify 사이트가 연구실 계정 소유인지
- [ ] Notion 통합(토큰)이 **연구실 공용 계정**으로 발급된 것인지 (개인 토큰이면 새로 발급)
- [ ] 토큰을 새로 발급했다면 Netlify Environment variables 의 `NOTION_TOKEN` 교체
- [ ] 새 통합을 9개 DB 각각에 **연결(Connections)** 했는지
- [ ] 교체 후 Trigger deploy 가 성공하는지

## 8. 도움을 요청할 때 함께 보내 주세요

이것만 있으면 원인 찾기가 훨씬 빠릅니다.

1. 문제가 보이는 **페이지 주소**
2. **무엇이** 어떻게 보여야 하는데 어떻게 보이는지
3. Netlify Deploys 에서 그 배포의 **로그** (실패했다면 특히)
4. Notion 에서 방금 무엇을 고쳤는지
